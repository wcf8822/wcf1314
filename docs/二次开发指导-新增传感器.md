## 1. 开写之前：必须向厂商确认的信息

**没有这张表就不要动代码。** 历史上多次返工都源于协议细节未确认。

| # | 需要确认的项 | 为什么要问 | 本项目对应位置 |
|---|---|---|---|
| 1 | 从站地址（Modbus ID） | 决定 `rs485.h` 宏值，且**必须 ≤ 99**（见 §8） | `hardware/rs485.h` |
| 2 | 串口参数（波特率/数据位/校验/停止位） | 本仪表 RS485 固定 **9600 8N1**，若探头不同则需评估 | `Core/Src/usart.c` USART3 |
| 3 | 支持的**功能码** | 决定组帧字节 `tx_buf[1]`（本项目大量使用 0x03 读、0x06 写单寄存器） | 驱动文件 |
| 4 | **完整寄存器表** | 地址、位宽（16/32 位）、有无符号、单位、倍率、字节序 | 驱动文件 + 本文档 |
| 5 | 寄存器地址是 **0-based 还是 1-based** | 协议书写 40001 这类编号时容易差 1 | 组帧 `tx_buf[2..3]` |
| 6 | 测量值寄存器块：**起始地址 + 寄存器个数** | 决定一次读多少，以及解析下标 | `GetValue()` + `UpdateXxx()` |
| 7 | 设备识别/握手指令（"在不在"） | 搜索轮询要用，决定 `GetModbusId()` 帧 | `GetModbusId()` |
| 8 | 写保护机制：是否需要先"写使能" | 海发系列需要 open/close，禹山/昇辉多数不需要 | §6 范例 C |
| 9 | 各类校准指令（零点/斜率/多点）及写入值 | 决定校准流程与 `Set_Cal()` 参数 | §4 Step 5 |
| 10 | 恢复出厂指令与写入值 | 决定 `ClearCal()` 帧 | 例：DY56 写 `0x0000=0xFEFE` |
| 11 | **典型收发帧示例**（抓包） | 唯一的验收标准 | 状态机断言依据 |
| 12 | CRC 字节序（低字节在前？） | 标准 Modbus RTU 是低字节在前，须确认 | `SetCrc()` 已按低前实现 |
| 13 | 是否存在"写指令回显" | 影响日志判读（见 §9 坑 6） | —— |
| 14 | SN 号 / 硬件版本 / 软件版本是否可读 | 决定传感器信息页是否显示 | `SetSN_SH()` |

### 1.1 ID 分配前的检查

```bash
# 列出所有已占用的 Modbus ID，挑一个没用过的
grep -n "ModbusID\|_Modbus " code/hardware/rs485.h
```

已占用 ID 一览见 `README.md` §5。**ID 唯一性是硬约束**，冲突会导致两个传感器互相抢答（`rx_buf[0]` 分发到错误的处理函数）。

## 2. 数据流全景：一次完整的传感器生命周期

### 2.1 连接握手（上电/插拔后只走一次）

```text
主循环(main_loop)                     rs485_Search_Sensor()            驱动+状态机
      │                                      │                              │
      │  每 600ms rs485_TimHandle 置 need_sent│                              │
      ├──────────────────────────────────────┤                              │
      │                                      │  GetModbusId() 组帧          │
      │                                      ├─────────────────────────────▶│
      │  rs485_SendBuf() → HAL_UART_Transmit → 传感器 ───应答──────────────▶│ 空闲中断
      │                                      │                              │ rx_flag=1
      │  rs485_DataHandle()                  │                              │
      │   ├ CheckCrc()  校验                 │                              │
      │   ├ switch(rx_buf[0]) 按地址分发     │                              │
      │   └──────────────────────────────────┼──▶ Xxx_DataHandle()          │
      │                                      │     case GetModbusId:        │
      │                                      │       DO_AddProbe(id)  ← 挂载设备节点
      │                                      │       rs485_DevicePlus()
      │                                      │       清所有业务标志 ★重要
      │                                      │       SetSN_SH(正确的通道指针)
      │                                      │       GetSalinity() ← 串起读链
      │                                      │                              │
      │                          读链：盐度 → 气压 → 温度偏移 → ...         │
      │                                      │                              │
      │                                      │       DO_SetIsInit()  ← 握手完成
      ▼                                      ▼                              ▼
   进入循环读数
```

### 2.2 循环读数（每 600 ms 一轮）

```text
rs485_TimHandle(600ms) → need_sent=1
      ↓
main_loop → rs485_SendBuf()
      ↓
rs485_Search_Sensor()   ┌─ 已识别到 2 个探头 → switch(comA/comB 的 id) → 读数指令
                        ├─ 只识别到 1 个     → TwoCircular_Flag 翻转：
                        │                       真 → 读数指令
                        │                       假 → 搜索下一个探头
                        └─ 一个都没识别到    → 搜索下一个探头
      ↓
传感器应答 → 空闲中断 → rs485_DataHandle() → CheckCrc → Xxx_DataHandle()
      ↓
case GetTempTwoDO:  close_circle() 关循环发送
                    UpdateXxx(ptd, &rx_buf[3])   ← 解析原始字节
                    DO_SetIsGetedValue(ptd)      ← 标记"已拿到数据"
      ↓
UpdateXxx() 内部：  字节 → 工程值 → 累加 3 次 → 滑动平均 → snprintf 显示缓冲 → 落盘显示
```

### 2.3 用户改参数（如设置盐度）

```text
按键 OK（界面层）                          状态机层                      传感器
      │                                        │                          │
      │ 1. setting_SetSalinity(v) 存本地配置     │                          │
      │ 2. switch(id) case XX:                  │                          │
      │      Set_XX_Sal_Flag(1)   ← 只置标志    │                          │
      │      Set_XX_Sal_Value(v*100)            │                          │
      │      Xxx_rs485_Set_Cmd_open(ptd) ──────▶│ sent_type = Start        │
      │                                          │ 写使能 0x06 ────────────▶│
      │                                          │ 应答 → case Start:       │
      │                                          │   查标志 → 真正写寄存器  │
      │                                          │   Set_Sal(v) ───────────▶│
      │                                          │ 应答 → case SetSalinity: │
      │                                          │   Set_Cmd_close() ──────▶│
      │                                          │ 应答 → case Stop:        │
      │                                          │   generate_MessageBox()  │
      ▼                                          ▼                          ▼
   成功弹窗
```

> **这是本项目最重要的设计模式**：界面层**不直接**发写指令，只置「标志 + 数值」并发写使能；
> 真正的写寄存器由状态机在 `DO_SendType_Start` 的应答分支里做。原因见 §7.1。

## 3. 分层契约：谁负责什么

严格遵守下表的职责边界，是本项目能容纳 30+ 种传感器而不失控的原因。

| 层 | 文件 | **只负责** | **禁止** |
|---|---|---|---|
| 驱动层 | `logic/Xxx.c/.h` | ① 组帧：填 `tx_buf[]` + `SetCrc()` + `rs485_SetSentType()`<br>② 解析：`rx_buf` 字节 → `DOProbe_t` 字段 / 显示缓冲 | ❌ 不调 `rs485_SendBuf()`<br>❌ 不碰 `interfacial_*`<br>❌ 不写状态机分支逻辑 |
| 状态机层 | `hardware/data_processing.c` | 唯一的"收到什么之后发什么"决策点；所有业务流程编排 | ❌ 不写组帧细节（调驱动层函数）<br>❌ 不做数值滤波<br>❌ 不直接响应按键 |
| 设备层 | `logic/dissolved_oxygen.c` | 设备链表挂载、`SENSOR_TYPE` 归类、显示名、滑动平均队列初始化、气压/盐度自动下发 | ❌ 不组帧 |
| 界面层 | `gui/interfacial.c` | 按键事件 → 写 `setting_*` + 置标志 + 发写使能；搜索轮询时序 | ❌ 不直接发参数写指令<br>❌ 不解析 `rx_buf` |
| 显示层 | `gui/generate_page.c` | 只读显示：菜单项、单位、标签、按型号分支 | ❌ 不参与任何协议 |
| 配置层 | `logic/setting.c/.h` | 持久化配置的 getter/setter | ❌ 不带任何协议 |

## 4. 七步改造流程（含可复制模板）

下文以新增一款假想传感器 **`XX`（Modbus ID = 88）** 为例。
**把 `XX` 替换为你的型号缩写，`XX_ModbusID` 替换为你的宏名。**

### Step 1 — `hardware/rs485.h`：定义 Modbus ID

在 ID 宏区（`rs485.h:20-63`）追加一行。**插入到同类传感器附近**便于阅读：
```c
/* ---------- hardware/rs485.h ---------- */
#define DO_HF_DY56_ModbusID 81
#define XX_ModbusID 88            // ← 新增；必须 ≤ 99
```

如果该探头属于**全新的测量类型**（现有 `SENSOR_TYPE` 枚举里没有），还需在 `SENSOR_TYPE`（`rs485.h:67-87`）中追加：

```c
typedef enum{
    TYPE_DO = 0,
    ...
    TYPE_NONE,
    TYPE_XX              // ← 新增类型（必须加在 TYPE_NONE 之前，或调整 TYPE_NONE 位置）
}SENSOR_TYPE;
```

> ⚠️ `TYPE_NONE` 被当作"未接传感器"哨兵值使用（`rs485_SetSensorType(TYPE_NONE)`）。
> 追加新类型时请把 `TYPE_XX` 插到 `TYPE_NONE` **前面**，并全局检查是否有 `== TYPE_NONE` 的判定依赖其数值。
> **最稳妥的做法：尽量复用现有类型**（例如新浊度探头继续用 `TYPE_Tur`），避免动枚举。

#### 2.2 源文件模板 `logic/XX.c`

```c
#include "XX.h"
#include "setting.h"
#include "calculate.h"
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include "rtc.h"
#include "dissolved_oxygen.h"

/* ============================================================
 *  模块私有变量 —— 必须全部 static！
 *  （见 §9 坑 1：不加 static 会与其他型号文件产生 multiple definition）
 * ============================================================ */
static uint8_t Param_Flag = 0, Zero_Flag = 0, Slp_Flag = 0, ClearCal_Flag = 0;
static int16_t Param_Value = 0;

/* ---------------- 标志与数值的 getter / setter ---------------- */
uint8_t Get_XX_Set_Param(void)          { return Param_Flag; }
void    Set_XX_Param_Flag(uint8_t v)    { Param_Flag = v; }
int16_t Get_XX_Set_Param_Value(void)    { return Param_Value; }
void    Set_XX_Param_Value(int16_t v)   { Param_Value = v; }

uint8_t Get_XX_Set_Zero_Cal(void)       { return Zero_Flag; }
void    Set_XX_Zero_Flag(uint8_t v)     { Zero_Flag = v; }
uint8_t Get_XX_Set_Slp_Cal(void)        { return Slp_Flag; }
void    Set_XX_Slp_Flag(uint8_t v)      { Slp_Flag = v; }
uint8_t Get_XX_ClearCal_Flag(void)      { return ClearCal_Flag; }
void    Set_XX_ClearCal_Flag(uint8_t v) { ClearCal_Flag = v; }

/* ============================================================
 *  组帧函数
 *  统一套路：
 *    tx_buf[0] = 从站地址
 *    tx_buf[1] = 功能码          (0x03 读保持寄存器 / 0x06 写单寄存器)
 *    tx_buf[2] = 起始地址 高字节
 *    tx_buf[3] = 起始地址 低字节
 *    tx_buf[4] = 寄存器个数 高字节 (读) 或 数据 高字节 (写)
 *    tx_buf[5] = 寄存器个数 低字节 (读) 或 数据 低字节 (写)
 *    SetCrc(buf, tx_size = 8)   ← 8 = 含 2 字节 CRC 的整帧长度
 *    rs485_SetSentType(语义)     ← 状态机据此判断当前在等什么应答
 * ============================================================ */

/* 握手：设备在不在。返回值格式由你自己定义，只要应答能过 CRC 即可 */
void XX_rs485_GetModbusId(void)
{
    rs485_usart.tx_buf[0] = XX_ModbusID;
    rs485_usart.tx_buf[1] = 0x03;
    rs485_usart.tx_buf[2] = 0x00;
    rs485_usart.tx_buf[3] = 0x00;   /* 起始地址 0x0000 */
    rs485_usart.tx_buf[4] = 0x00;
    rs485_usart.tx_buf[5] = 0x01;   /* 读 1 个寄存器 */

    SetCrc(rs485_usart.tx_buf, rs485_usart.tx_size = 8);
    rs485_SetSentType(DO_SendType_GetModbusId);
}

/* 读取测量值：一次读 N 个连续寄存器 */
void XX_rs485_GetValue(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;

    rs485_usart.tx_buf[0] = XX_ModbusID;
    rs485_usart.tx_buf[1] = 0x03;
    rs485_usart.tx_buf[2] = 0x00;
    rs485_usart.tx_buf[3] = 0x02;   /* 起始地址 0x0002 */
    rs485_usart.tx_buf[4] = 0x00;
    rs485_usart.tx_buf[5] = 0x04;   /* 读 4 个寄存器 = 8 字节 */

    SetCrc(rs485_usart.tx_buf, rs485_usart.tx_size = 8);

    rs485_SetCircularSentStatus();                        /* ← 标记"循环发送中" */
    rs485_SetSentType(DO_SendType_GetTempTwoDO);          /* ← 复用：代表"测量值应答" */
}

/* 写单个寄存器：把两个字节塞进去（大端：高字节在前） */
static void XX_Write_Reg(uint8_t reg_hi, uint8_t reg_lo, int16_t value,
                         rs485_sent_type sent_type)
{
    rs485_usart.tx_buf[0] = XX_ModbusID;
    rs485_usart.tx_buf[1] = 0x06;             /* 写单寄存器 */
    rs485_usart.tx_buf[2] = reg_hi;
    rs485_usart.tx_buf[3] = reg_lo;
    rs485_usart.tx_buf[4] = (uint8_t)(value >> 8);   /* 高字节 */
    rs485_usart.tx_buf[5] = (uint8_t)(value);        /* 低字节 */

    SetCrc(rs485_usart.tx_buf, rs485_usart.tx_size = 8);
    rs485_SetCircularSentStatus();
    rs485_SetSentType(sent_type);
}

/* 写使能（若协议无写保护，此函数写成空实现或直接跳到下一步） */
void XX_rs485_Set_Cmd_open(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x28, 0x5A5A, DO_SendType_Start);
}

/* 写禁止 */
void XX_rs485_Set_Cmd_close(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x28, 0x0000, DO_SendType_Stop);
}

/* 设置参数 */
void XX_rs485_Set_Param(PtrToDOProbe ptd, int16_t value)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x10, value, DO_SendType_SetSalinity);   /* 语义按实际复用 */
}

/* 零点校准 */
void XX_rs485_Set_Zero_Cal(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x01, 0x0003, DO_SendType_SetZeroCal);
}

/* 斜率校准 */
void XX_rs485_Set_Slp_Cal(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x01, 0x0004, DO_SendType_SetFullCal);
}

/* 恢复出厂 */
void XX_rs485_ClearCal(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;
    XX_Write_Reg(0x00, 0x00, 0xFEFE, DO_SendType_HyphiveClearCal);
}

/* 读取参数（用于连接握手阶段回填本地值） */
void XX_rs485_Get_Param(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;

    rs485_usart.tx_buf[0] = XX_ModbusID;
    rs485_usart.tx_buf[1] = 0x03;
    rs485_usart.tx_buf[2] = 0x00;
    rs485_usart.tx_buf[3] = 0x10;
    rs485_usart.tx_buf[4] = 0x00;
    rs485_usart.tx_buf[5] = 0x01;

    SetCrc(rs485_usart.tx_buf, rs485_usart.tx_size = 8);
    rs485_SetCircularSentStatus();
    rs485_SetSentType(DO_SendType_GetTemperature);   /* ← 复用字段存"参数应答" */
}

/* ============================================================
 *  解析函数
 *  规则：Modbus 线上是大端（高字节在前），STM32 是小端，
 *        所以 dat[0]=高字节 → 放进 value_arr[1]；dat[1]=低字节 → value_arr[0]。
 * ============================================================ */

/* 解析一个有符号 16 位参数 */
void XX_SetParamArr(PtrToDOProbe ptd, uint8_t *dat)
{
    int16_u tmp;
    if(ptd == NULL) return;
    tmp.value_arr[0] = dat[1];      /* 低字节 */
    tmp.value_arr[1] = dat[0];      /* 高字节 */
    ptd->NH4_Vol.value_f = (float)tmp.value_f / 100.0f;   /* 倍率按协议 */
}

/* 解析测量值块（起始地址 0x0002，共 4 个寄存器 = 8 字节） */
void XX_UpdateTemp2DO(PtrToDOProbe ptd, uint8_t *dat)
{
    float value_temp = 0.0f;
    uint16_u u16;

    if(ptd == NULL) return;

    /* dat[0..1] → 主测量值（0x0002），倍率 100 表示两位小数 */
    u16.value_arr[0] = dat[1];
    u16.value_arr[1] = dat[0];
    ptd->DOmgl.value_f = (float)u16.value_f / 100.0f;

    /* dat[2..3] → 温度（0x0003），倍率 10 */
    u16.value_arr[0] = dat[3];
    u16.value_arr[1] = dat[2];
    ptd->temperature.value_f = (float)u16.value_f / 10.0f;

    /* 首次拿到数据：直接给值，不参与累计 */
    if(ptd->is_FirstGetValue)
    {
        ptd->is_FirstGetValue = 0;
        ptd->last_DOmgl = ptd->DOmgl.value_f;

        snprintf(ptd->DOmgl_arr,       7, "%6.2f", ptd->DOmgl.value_f);
        snprintf(ptd->temperature_arr, 6, "%5.1f", ptd->temperature.value_f);
    }
    else
    {
        /* 累计 3 帧再平均，抑制单帧抖动 */
        ptd->DOmgl_sum      += ptd->DOmgl.value_f;
        ptd->temperature_sum += ptd->temperature.value_f;

        CheckValueLock(ptd);                       /* 自动锁定的统一入口，必须调 */
        ptd->last_DOmgl = ptd->DOmgl.value_f;

        if(++ptd->update_count >= 3)
        {
            value_temp = ptd->DOmgl_sum / (float)ptd->update_count;

            /* 滑动平均（按本传感器类型取开关与次数） */
            if(setting_GetIsOpen_SlideAvg_Tur() && setting_GetSlideAvgTimes_Tur() >= 2)
            {
                if(is_FirstFilter)
                {
                    is_FirstFilter = 0;
                    filter_clear(&(ptd->queue_domgl));
                }
                filter_inset2arr(&(ptd->queue_domgl), value_temp);
                value_temp = filter_get_avg(&(ptd->queue_domgl));
            }
            else
            {
                is_FirstFilter = 1;
            }

            /* 被锁定时不刷新显示，但仍继续采样 */
            if(!DO_GetValueLocked(ptd))
            {
                snprintf(ptd->DOmgl_arr,       7, "%6.2f", value_temp);
                snprintf(ptd->temperature_arr, 6, "%5.1f",
                         ptd->temperature_sum / (float)ptd->update_count);
            }

            ptd->update_count    = 0;
            ptd->DOmgl_sum       = 0.0f;
            ptd->temperature_sum = 0.0f;
        }
    }
}

/* SN / 硬件版本 / 软件版本。协议读不到时用固定值（见 §9 坑 5） */
void XX_SetSN_SH(PtrToDOProbe ptd)
{
    if(ptd == NULL) return;

    /* SN 缓冲固定 12 个可见字符：ptd->SN[0..11]，SN[12] 已由 DO_AddProbe 置 '\0' */
    ptd->SN[0]='X';  ptd->SN[1]='X';  ptd->SN[2]='-';
    ptd->SN[3]='0';  ptd->SN[4]='0';  ptd->SN[5]='1';
    ptd->SN[6]=' ';  ptd->SN[7]=' ';  ptd->SN[8]=' ';
    ptd->SN[9]=' ';  ptd->SN[10]=' '; ptd->SN[11]=' ';

    /* 注意：若 SN 以 'H','F' 开头会被 DO_SetSN() 判为海发厂商，
       进而改变校准菜单显示。不需要该副作用时请避开这两个字母。 */
    ptd->HWV[0] = '1'; ptd->HWV[1] = '.'; ptd->HWV[2] = '0'; ptd->HWV[3] = '\0';
    ptd->SWV[0] = '1'; ptd->SWV[1] = '.'; ptd->SWV[2] = '0'; ptd->SWV[3] = '\0';
}
```

> **关于 `HWV` / `SWV`**：数组是 `char HWV[5]`，最多 4 个字符 + `'\0'`。
> **关于 `SN`**：`uint8_t SN[17]`，但全项目按 **12 个可见字符**使用，`SN[12] = '\0'` 由 `DO_AddProbe()` 统一设置。

## 6. 三类范例：由浅入深

按复杂度选择最接近的范例照抄。

### 范例 A — 最简单：单值测量 + 单点校准（照 `ORP_DR31`）

**规模**：驱动 `logic/ORP_DR31.c` 仅 142 行，状态机 `ORP_DR31_DataHandle()` 仅 62 行。

**协议特征**：无写保护、无读链、无多参量。

**状态机骨架（4 个 case 即可）**：

```text
GetModbusId   → DO_AddProbe + DevicePlus + DO_SetIsInit + 清 GetCircularSent_Flag
GetTempTwoDO  → close_circle + UpdateTemp2DO + DO_SetIsGetedValue
SetKB         → close_circle + 校准成功弹窗
HyphiveClearCal → close_circle + 恢复出厂成功弹窗
```

**适用**：ORP、pH、电导率、浊度、余氯等大多数单值传感器。

### 范例 B — 中等：多参量 + 两点校准（照 `DO_shenghui` / `Tur_shenghui`）

**协议特征**：一次读回多个参量（主值 + 温度 + 状态字），需要 `GetDOmgL` / `GetDOPercent` 分帧读取，
或有多个校准点（第一点/第二点/第三点）。

**关键差异**：

- `GetValue()` 拆成多个函数（`GetVol()`、`GetDOPercent()`、`GetDOmgL()`），
  用 `GetCircularSent_Flag_0` / `GetCircularSent_Flag_1` 做**轮转**，避免每条都发同样的帧。
- `UpdateTemp2DO()` 里需要 `filter_init(&(ptd->queue_value), ...)` 等额外队列（`COD` 会用到 `queue_value`）。
- 校准多一个 `PAGE_5_xxx_TWO` / `THREE` 页面分支。

### 范例 C — 最复杂：写使能三步式 + 连接读链 + 恢复出厂（照 `DO_HaiFa_DY56`）

**规模**：驱动 `logic/DO_HaiFa_DY56.c` 571 行，状态机 `DO_HF_DY56_DataHandle()` 210 行。

**协议特征**：

```text
写使能 open ：06 00 28 5A 5A
写参数       ：06 00 13 xx xx   （盐度，×100）
零点校正     ：06 00 01 00 03
满氧校正     ：06 00 01 00 04
温度偏移     ：06 00 19 xx xx   （×100，int16）
写禁止 close：06 00 28 00 00
恢复厂家设置 ：06 00 00 FE FE
读测量值     ：03 00 03 00 08   → 8 寄存器 = 16 字节
```

**测量值块解析对照表**（`DO_HaiFa_DY56_UpdateTemp2DO()`）：

| `dat[]` 下标 | 寄存器 | 含义 | 倍率 |
|---|---|---|---|
| `dat[0..1]` | `0x0003` | 溶解氧 mg/L | 100 |
| `dat[6..7]` | `0x0006` | 饱和度 % | 10 |
| `dat[10..11]` | `0x0008` | 盐度 ‰ | 100 |
| `dat[12..13]` | `0x0009` | 气压 kPa | 100 |
| `dat[14..15]` | `0x000A` | 温度 ℃ | 100 |

**连接读链**（`GetModbusId` 应答里启动）：

```text
GetModbusId → GetSalinity(0x0013) → GetPressure(0x0012) → GetTemperature(0x0019)
                                                        → DO_SetIsInit → 进入循环读数
```

**标志驱动的写流程**（`SentType == Start` 应答里按优先级分派）：

```text
ClearCal_Flag > Param/Sal_Flag > Press_Flag > Temp_Cal_Flag > Zero_Flag > Full_Flag
```

**恢复出厂的 6 步串联**（用同一个 `ClearCal_Flag` 贯穿整个流程）：

```text
open → ClearCal(0x0000=0xFEFE) → 盐度=0 → 气压=10132 → 温度偏移=0 → close
        ↑ HyphiveClearCal 分支   ↑ SetSalinity 分支  ↑ SetPressure 分支   ↑ SetTemp 分支
```

**复杂范例的两个额外要点**：

1. **写成功后要回填本地值**。DY56 第一次温度校准正常、第二次算错，根因就是
   `SetTemp` 应答里没有回填 `NH4_Vol`（温度偏移量缓存），第二次仍用连接时读到的旧值（通常 0）
   去算 `offset = 标准值 − 实测值 + 旧偏移`。
2. **恢复出厂要同步本地 `setting` 缓存**。只写传感器寄存器会导致主循环
   `DO_UpdatePressSal()` 检测到「本地旧值 ≠ 探头新值」而把旧参数自动写回，
   现象是「恢复出厂流程发两遍、参数没变」。必须在收尾时补：

   ```c
   setting_SetSalinity(0.0f);
   setting_SetAirCompensate(101.32 - bmp280_GetPress());
   set_SalArr(0.0f);
   set_PressArr(bmp280_GetPress());
   SettingToFlash();
   ```

## 7. 状态机与标志设计规范

### 7.1 为什么界面层只置标志、不发写指令？

因为 **Modbus 是半双工单总线，且仪表同一时刻只能有一个待处理事务**。
`rs485_usart` 只有一份 `tx_buf` / `sent_type`，如果界面层按下按键时直接组帧发送，
会与 600 ms 的循环读数发送互相覆盖，导致：

- 写指令被读数指令顶掉 → 参数没写进去；
- 或读数应答被当成写指令应答处理 → 状态机错乱。

因此设计成：

```text
界面层：置标志 + 发写使能（open）
   ↓
状态机在 Start 应答中：读标志 → 发真正的写命令（清标志）
   ↓
状态机在写应答中：继续下一步 或 发 close
   ↓
状态机在 Stop 应答中：弹成功窗 + 恢复循环读取
```

**`rs485_SetCircularSentStatus()` 的作用**：置位后，`rs485_SendBuf()` 不再触发搜索逻辑，
且业务代码（如 `DO_UpdatePressSal`）通过 `!rs485_GetCircularSentStatus()` 判断"当前有事务在跑，先别插队"。
写流程结束后必须调 `close_circle()`（= `ClearCircularSentStatus()` + `ClearResendCount()`）解除。

### 7.2 标志必须在"重连点"清零

**重连点 = `case DO_SendType_GetModbusId` 的应答分支。**

原因：任何写流程都可能被"重发次数超限 → 判定断连"打断（`RESEND_MAX = 4`），
此时流程停在中间某一步，已置的标志不会被清。
设备重新插上后走读链，这些残留标志会在**下一次任意写操作**的 `Start` 应答里被误触发，
把用户没打算写的参数写入（例如恢复出厂流程被打断 → 之后改盐度却触发了恢复出厂）。

```c
case DO_SendType_GetModbusId:
    if(rs485_usart.rx_buf[1] == 0x03)
    {
        DO_AddProbe(XX_ID);
        rs485_DevicePlus();

        /* ★ 重连 = 干净状态 */
        Set_XX_ClearCal_Flag(0);
        Set_XX_Param_Flag(0);
        Set_XX_Zero_Flag(0);
        Set_XX_Slp_Flag(0);
        /* ... 所有你定义的标志都要列全 ... */

        GetCircularSent_Flag = 0;
        /* ... */
    }
    break;
```

### 7.3 双探头指针选择：统一用三元表达式

⚠️ 这是**最容易出错的一行**。

`get_COMADo()` **永远**返回 A 通道指针，与"当前这个应答来自哪个探头"无关。
一个总线上的第二个探头挂在 `comB_DO`，如果处理函数里硬编码 `get_COMADo()`，
数据会被写到**错误的设备节点**上（典型现象：B 通道探头的 SN / 数值显示空白，A 通道显示错误数据）。

**统一写法**（全项目一致，直接复制）：

```c
get_COMADo()->modbus_id == XX_ModbusID ? get_COMADo() : get_COMBDo()
```

虽然啰嗦，但**请勿自创简写**，以便后续全局替换与审查。

### 7.4 `close_circle()` 的调用时机

| 场景 | 是否调 `close_circle()` |
|---|---|
| 收到测量值应答 | ✅ 必须（这一次事务结束了） |
| 收到读链中间环节应答，还要发下一环 | ✅ 调用后再发下一环 |
| 收到写应答，还要发下一步 | ✅ 调用后再发下一步 |
| 收到读链最后一环应答 | ✅ |
| 发送前（组帧时） | ❌ 不调 |
| `GetModbusId` 应答 | ❌ 按现有实现不调（保留搜索状态） |

### 7.5 应答合法性判断三要素

`rs485_GetSentType()` 只说明"我在等什么"，**不能保证收到的一定是那个应答**
（可能是上一轮的迟到应答、其他设备串扰、或传感器的写指令回显）。因此每个 case 内部必须再校验：

```c
/* ① 功能码：0x03 读 / 0x06 写 */
if(rs485_usart.rx_buf[1] == 0x03)

/* ② 读应答：校验字节数（registers × 2） */
&& rs485_usart.rx_buf[2] == 0x08      /* 4 个寄存器 */

/* ③ 写应答：校验寄存器地址高字节，避免"写 0x00xx" 与 "写 0x01xx" 混淆 */
&& rs485_usart.rx_buf[2] == 0x00

/* ④ 恢复出厂：校验写入值回显 */
&& rs485_usart.rx_buf[4] == 0xFE
```

## 9. 常见坑清单（实测踩过）

### 坑 1 ★★★ 克隆文件忘加 `static` → 链接报 multiple definition

从同类型传感器复制文件时，模块内的标志/数值变量会与源文件**重名且同为外部链接**。

```c
/* ❌ DO_HaiFa_DY56.c 从 DY12 克隆后 */
uint8_t Sal_Flag = 0, Press_Flag = 0, Zero_Flag = 0, Full_Flag = 0;
int16_t SalValue = 0, PresssValue = 0, Zero_Value = 0, Full_Value = 0;
/* → 与 DO_HaiFa_DY12.c 中的同名符号冲突：multiple definition */

/* ✅ 全部加 static，变成文件内部链接 */
static uint8_t Sal_Flag = 0, Press_Flag = 0, Zero_Flag = 0, Full_Flag = 0;
static int16_t SalValue = 0, PresssValue = 0, Zero_Value = 0, Full_Value = 0;
```

**规则：驱动文件里所有非 API 的模块变量一律 `static`。** 只有 getter/setter 函数对外可见。

### 坑 2 ★★ `DEBUG` 宏让 `STATIC` 失效

`Core/Inc/main.h` 中：

```c
#define DEBUG 1
#if DEBUG
#define STATIC              /* ← DEBUG=1 时 STATIC 展开为空！ */
#else
#define STATIC static
#endif
```

于是 `hardware/rs485.c:18` 的 `STATIC uint8_t is_change_senesor = 0;` 当前是**全局符号**。

- 新增代码请**直接用 `static` 关键字**，不要用 `STATIC` 宏。
- 发布版本可考虑把 `DEBUG` 置 0，或清理掉 `STATIC` 的用法。

### 坑 3 ★★★ 重连点不清标志 → 误触发写流程

见 §7.2。现象：**恢复出厂做到一半拔线，重插后改任意参数都会触发恢复出厂。**

### 坑 4 ★★★ 恢复出厂不同步本地 `setting` → 参数被自动写回

见 §6 范例 C 的要点 2。
现象：**恢复出厂后参数没变**（其实是变了又被自动写回）。

### 坑 5 ★★ 双探头时 SN 写到错误通道

见 §7.3。现象：**第二个探头（comB）的 SN / 硬件版本 / 软件版本显示空白。**

### 坑 6 ★ 串口日志里写指令出现两次是"回显"，不是重发

传感器对 `0x06` 写指令会在应答之外**回显一次请求帧**。
不要据此认为是超时重发而去改 `RESEND_MAX` 或重发逻辑。

**判据**：回显帧的内容与请求帧**完全一致**；重发则会在 `RS485_CIRCULAR_TIM`（600 ms）之后出现。

### 坑 7 ★★★ 忘改 `Sersor_Number`

见 §5.1。现象：**新传感器永远搜不到**，且第 28 号以后的搜索分支都不执行。

### 坑 8 ★★ 忘注册 `.uvprojx`

现象：链接期 `undefined symbol`，或状态机函数根本没被编译进固件。

### 坑 9 ★★ `SetCrc()` 的 `len` 是"含 2 字节 CRC 的整帧长度"

```c
/* ✅ 正确：tx_size = 8，CRC 写在 buf[6]、buf[7] */
SetCrc(rs485_usart.tx_buf, rs485_usart.tx_size = 8);

/* ❌ 错误：写成 6，CRC 会写到 buf[4]、buf[5]，覆盖数据字节 */
SetCrc(rs485_usart.tx_buf, 6);
```

`SetCrc()` 实现（`Core/Src/usart.c:360`）：

```c
void SetCrc(uint8_t *buf, uint16_t len)
{
    uint16_t crc = CalCrc(buf, len - 2);   /* 计算不含 CRC 的部分 */
    buf[len - 2] = crc & 0xFF;             /* 低字节在前（标准 Modbus RTU） */
    buf[len - 1] = crc >> 8;
}
```

### 坑 10 ★ `rs485_DataHandle()` 会丢弃 `rx_size < 5` 的帧

短帧（如某些设备的 4 字节异常应答）在分发前就被丢弃，状态机收不到。
若协议确实存在短帧，需要修改 `data_processing.c:3469` 的门限判断。

### 坑 11 ★ 寄存器地址 0-based / 1-based 混淆

协议书写 `40001`、`30001` 这类编号时，实际地址要减 40001/30001。
例：`40003` → 地址 `0x0002` → `tx_buf[2]=0x00, tx_buf[3]=0x02`。
**先用 Modbus 调试助手确认一帧实测能通，再写代码。**

### 坑 12 ★ `manufacturer` 是垃圾值

`manufacturer` 只在 `DO_SetSN()` 里根据 SN 前两位赋值，且那个判断本身有 bug
（`ptd->SN[1] == 'L' && ptd->SN[1] == '0'` 恒为假）。

- **不要**在新增代码里依赖 `manufacturer` 做分支；
- `generate_cal_DO()` 中的相关判断必须**额外**加上 `modbus_id == XX_ModbusID`。

### 坑 13 ★ 忘记 `DO_SetIsGetedValue()`

现象：**数值在传感器上是对的，但界面一直显示"无信号"**。
`interfacial.c:9412` 用 `DO_GetIsGetedValue(get_CurDo())` 决定是否清除"无信号"提示。

### 坑 14 ★ 忘记 `DO_SetIsInit()`

现象：**仪表改气压/盐度不会自动下发到探头**。
`DO_UpdatePressSal()` 只在 `p->is_init == 1` 时才工作。

### 坑 15 ★ `close_circle()` 只关"循环发送"，不关"需要发送"

`close_circle()` = `rs485_ClearCircularSentStatus()` + `rs485_ClearResendCount()`。
它**不会**清 `rs485_need_sent`。若发现发送节奏异常，检查 `need_sent` 的置位源（`rs485_TimHandle`，600 ms）。

## 12. 附录：Modbus 帧格式与工具函数

### 12.1 本项目使用的两种帧格式

#### 读保持寄存器（0x03）请求 / 应答

```text
请求： [从站地址][0x03][起始地址Hi][起始地址Lo][寄存器数Hi][寄存器数Lo][CRC_Lo][CRC_Hi]   共 8 字节
应答： [从站地址][0x03][字节数][数据0_Hi][数据0_Lo][数据1_Hi][数据1_Lo]...[CRC_Lo][CRC_Hi]
```

因此解析入口固定是 **`&(rs485_usart.rx_buf[3])`**，字节数在 `rx_buf[2]`。

#### 写单寄存器（0x06）请求 / 应答

```text
请求： [从站地址][0x06][寄存器Hi][寄存器Lo][数据Hi][数据Lo][CRC_Lo][CRC_Hi]   共 8 字节
应答： 与请求完全相同（回显）
```

因此应答校验常用 `rx_buf[1] == 0x06`（功能码）+ `rx_buf[2] == 0x00`（寄存器地址高字节）
或 `rx_buf[4] == 0xFE`（写入值回显）。

### 12.2 字节序转换模板

线上是**大端**（高字节在前），STM32 是**小端**。

#### 收（大端 → 小端）

```c
/* 无符号 16 位 */
uint16_u u16;
u16.value_arr[0] = dat[1];   /* 低字节 */
u16.value_arr[1] = dat[0];   /* 高字节 */
float f = (float)u16.value_f / 100.0f;

/* 有符号 16 位 */
int16_u i16;
i16.value_arr[0] = dat[1];
i16.value_arr[1] = dat[0];
float f2 = (float)i16.value_f / 100.0f;

/* 无符号 32 位（4 寄存器拼装，注意顺序） */
uint32_u u32;
u32.value_arr[0] = dat[3];
u32.value_arr[1] = dat[2];
u32.value_arr[2] = dat[1];
u32.value_arr[3] = dat[0];
```

> `int16_u.value_arr` 的类型是 `int8_t[2]`，赋值 `dat[1]`（可能是 200）会产生实现定义的转换，
> 但位模式保留，`value_f` 仍读回正确的 200。**这是既有代码的写法，可放心照抄。**

#### 发（小端 → 大端）

```c
/* 有符号/无符号 16 位 */
int16_t value = 1234;
rs485_usart.tx_buf[4] = (uint8_t)(value >> 8);   /* 高字节 */
rs485_usart.tx_buf[5] = (uint8_t)(value);        /* 低字节 */
```
